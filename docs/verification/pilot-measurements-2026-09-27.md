# 正式案例量測第一階段

2026-09-27：既有 React 專案評估頁新增「正式案例量測」，不引入新 UI framework、不變更原 Task/Run 或登錄集合。

## 定義與保護

來源是平台 PostgreSQL 的不可變 cohort、Task 綁定、attempt ordinal 與既有 Release gate。每個集合固定 20 案；無 Run、未綁定、失敗、取消與檢查失敗均保留分母。依持久化 attempt ordinal 選最新版；順序無法確認時不猜測版本。

| 欄位 | 定義與限制 |
|---|---|
| 目前可交付 | 逐案重新呼叫既有 Release 檢查，要求 RELEASE_READY、核准與交付識別；不是只數歷史 release 表列 |
| 無法確認 | 順序未驗證或讀取／證據檢查錯誤，獨立呈現，不視為零案或成功 |
| 準備版本 | 正式集合所有 Run，包括失敗及取消 |
| 補正版本 | 有 parent_run_id 的 Run；不把自動檢查、頁面點擊或模型 token 誤當人工介入 |
| 總經過時間 | 首版建立到目前交付核准，包含失敗、修訂與等待；無可用核准時間、負值、缺時區時為 null，不補零 |
| 尚缺量測 | 首次通過率、人工操作時間／基準、改善率、成本維持 null；不以交付率替代情境驗收率 |

Endpoint：`GET /api/projects/{project_id}/pilot-measurements`。畫面由使用者按「重新量測正式案例」觸發；唯讀、不執行模型／Hop／DDL，不增加平台控制事件。逐案檢查的起迄時間可見，不宣稱全組是同一時點的原子快照。單案讀取失敗不會洩露原始例外或機密；集合讀取失敗回傳 503，不假裝空集合。

這次指標設計參照 design-kpis 技能的來源、計算定義與防誤導原則；依使用者要求沿用既有工作台，而非建立替代 dashboard。沒有使用示意工時、成功率或改善幅度。
