## 跨頁草稿缺陷與修正

新建 Task 跨頁草稿：

1. 從專案進入建立 Task，輸入名稱，不提交。
2. 按返回專案設定，再按建立 Task。
3. 實際：未詢問、未阻擋，名稱清空。
4. 預期：有草稿時阻擋離開並說明；提供明確取消草稿後離開方式。
5. 成功建立後應解除草稿保護，不能阻擋正常進入新 Task；提交／上傳中不得任意離開。

修正不可用永久 localStorage 保存機密或檔案內容；不能將模式切換保留
等同跨頁保護。需要覆蓋單檔與雙 CSV，包含目前隱藏的模式草稿。

已實作共用 TaskDraftBoundary，以表單狀態判定兩個模式是否有草稿或忙碌。
實際部署驗證：單檔名稱草稿阻擋返回；切至雙 CSV 後隱藏的單檔草稿仍阻擋
全域導覽；取消全部草稿後兩種模式名稱都清空，返回專案設定成功。
沒有保存表單至 localStorage、刪除上傳檔案、建立 Task 或執行模型。
前端 build 通過。上傳／建立中分支仍待實測，不宣稱全流程通過。

成功建立追加實測：在既有合成 UI 專案填寫單欄 INT 範例來源，建立一筆純草稿
Task。頁面正確跳至新 Task 詳情，沒有被草稿保護擋住；重新整理後仍存在，
返回專案歷史顯示 1 / 1、NO_RUN、歷史交付 0。API 回讀確認同專案、CREATED、
run_count 0。未授權模型、未執行 Hop 或建立 Vertica 表；保留該 Task 作驗證紀錄。
此結果不包含雙 CSV 上傳／提交、重複請求防護或 ETL 驗收。

## 後續階段邊界

Task 頁籤追加實測：ArrowRight 依序切至需求／協作／產物／執行，End 至交付、
Home 回概覽，網址與畫面選取一致。390px 檢查發現需求來源卡片超寬至約 684px，
雖然整頁沒有水平捲軸但內容遭裁切。改用 minmax(0,1fr)、min-width:0 與長文字
換行後，部署實測卡片寬度約 322px、scrollWidth 320，不再超出來源容器。
協作／產物／交付在該次測試沒有超出 viewport 的可見元素；未操作任何核准。
已恢复正常 viewport；此結果仍不是所有表單、所有資料型態的完整視覺驗收。
